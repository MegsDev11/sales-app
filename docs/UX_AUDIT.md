## Systemic themes (highest leverage first)

### 1. No loading states — pages paint zeros and false empty states during async hydration

Gate every store- or fetch-backed page on a load flag before deciding what to render: use the store's isLoaded, or a local loading state initialized true and cleared in the fetch's finally. While loading, render skeletons (animate-pulse placeholder tiles/rows/charts and '—' in hero/stat figures), matching the established wireless/page.tsx house pattern. Only show real values or empty states after load completes. Also replace the 'if (isLoading || !allowed) return null' blank-screen pattern with a PageShell + PageHeader + skeleton so slow auth/data resolves never read as a broken or empty page.

_Affected (31):_ `app/(dashboard)/company/page.tsx`, `app/(dashboard)/dashboard/page.tsx`, `app/(dashboard)/analytics/page.tsx`, `app/(dashboard)/my-stats/page.tsx`, `app/(dashboard)/inbox/page.tsx`, `app/(dashboard)/surveys/page.tsx`, `app/(dashboard)/board/page.tsx`, `app/(dashboard)/coordination/page.tsx`, `app/(dashboard)/coordination/jobs/page.tsx`, `app/(dashboard)/coordination/timesheets/page.tsx`, `app/(dashboard)/coordination/time-off/page.tsx`, `app/(dashboard)/coordination/availability/page.tsx`, `app/(dashboard)/stock/page.tsx`, `app/(dashboard)/stock/vehicles/page.tsx`, `app/(dashboard)/stock/inventory/page.tsx`, `app/(dashboard)/stock/booked-out/page.tsx`, `app/(dashboard)/support/messages/page.tsx`, `app/(dashboard)/support/page.tsx`, `app/(dashboard)/support/clients/page.tsx`, `app/(dashboard)/support/towers/page.tsx`, `app/(dashboard)/wireless/layouts/page.tsx`, `app/(dashboard)/wireless/clients/page.tsx`, `app/(dashboard)/wireless/submissions/page.tsx`, `app/(dashboard)/wireless/page.tsx`, `app/(dashboard)/financial/page.tsx`, `app/(dashboard)/financial/fuel/page.tsx`, `app/(dashboard)/scheduler/page.tsx`, `app/(dashboard)/scheduler/agenda/page.tsx`, `app/(dashboard)/staff/page.tsx`, `app/(dashboard)/leads/[id]/page.tsx`, `components/department/placeholder-department-page.tsx`

### 2. Data-load failures are invisible or under-signaled — errors either ignored or styled as mild amber warnings

Destructure the store's error/dbError flag on every store-backed page and surface it at the top of the PageShell via the shared AlertBanner tone="danger" so a load failure is visibly distinct from a genuinely empty dashboard. Replace every hand-rolled amber (border-amber-200 bg-amber-50) error div with AlertBanner tone="danger" so real failures read as errors (red + icon + role semantics) and are consistent with the overview/financial pages. Change load-failure banners currently using tone="warn" to tone="danger".

### 3. Success and failure messages share one banner/color, so users can't tell them apart

Track success and error state separately and give each its own tone: render success confirmations in a positive/info tone (green/info AlertBanner) and failures in AlertBanner tone="danger". Never funnel both through a single amber div, a brand-blue text-primary line, or the same element — a 'Pick list sent' or 'booked back in' success must not look identical to 'Send failed'.

_Affected (7):_ `app/(dashboard)/coordination/requests/page.tsx`, `app/(dashboard)/stock/booked-out/page.tsx`, `app/(dashboard)/stock/requests/page.tsx`, `app/(dashboard)/stock/qr/page.tsx`, `app/(dashboard)/stock/client-qrs/page.tsx`, `app/(dashboard)/wireless/submissions/page.tsx`, `app/(dashboard)/staff/page.tsx`

### 4. Hardcoded palette colors bypass theme tokens and break in dark mode

Replace literal colors with design tokens everywhere: bg-white -> bg-card / bg-surface-elevated, bg-gray-50/bg-gray-100 -> bg-muted (and hover:bg-gray-50 -> hover:bg-muted/50), text-emerald/text-amber literals -> semantic tokens, and remove redundant text-white overrides on primary buttons so labels follow text-primary-foreground. This keeps cards, tracks, and rows readable and consistent when the shell is dark.

_Affected (10):_ `app/(dashboard)/analytics/page.tsx`, `app/(dashboard)/my-stats/page.tsx`, `app/(dashboard)/team/page.tsx`, `app/(dashboard)/support/towers/page.tsx`, `app/(dashboard)/support/page.tsx`, `app/(dashboard)/support/clients/page.tsx`, `app/(dashboard)/financial/fuel/page.tsx`, `app/(dashboard)/staff/page.tsx`, `app/(dashboard)/stock/requests/page.tsx`, `app/(dashboard)/wireless/layouts/page.tsx`

### 5. Weak and misleading empty states — no icon, no guidance, and no filter-vs-no-data distinction

Give every empty state a centered container with a relevant Lucide icon, a short headline, one line of helper copy, and a CTA where an action is the page's job (e.g. 'New layout', 'Create account'). Render reassurance sections unconditionally with an 'all caught up' body instead of returning null when empty. Branch copy so a filter miss ('No units match your search') is distinct from genuinely empty data ('No units yet'), preventing users from thinking inventory/clients are empty when a filter is active.

_Affected (19):_ `app/(dashboard)/dashboard/page.tsx`, `app/(dashboard)/analytics/page.tsx`, `app/(dashboard)/inbox/page.tsx`, `app/(dashboard)/surveys/page.tsx`, `app/(dashboard)/team/page.tsx`, `app/(dashboard)/coordination/jobs/page.tsx`, `app/(dashboard)/coordination/timesheets/page.tsx`, `app/(dashboard)/coordination/time-off/page.tsx`, `app/(dashboard)/stock/qr/page.tsx`, `app/(dashboard)/stock/requests/page.tsx`, `app/(dashboard)/stock/client-qrs/page.tsx`, `app/(dashboard)/support/messages/page.tsx`, `app/(dashboard)/support/clients/page.tsx`, `app/(dashboard)/wireless/layouts/page.tsx`, `app/(dashboard)/wireless/clients/page.tsx`, `app/(dashboard)/financial/page.tsx`, `app/(dashboard)/scheduler/page.tsx`, `app/(dashboard)/staff/page.tsx`, `components/department/placeholder-department-page.tsx`

### 6. Form fields rely on placeholder-only labels and unassociated labels (a11y failure)

Give every input/select/textarea a persistent visible <label> associated via htmlFor/id (or at minimum an aria-label), and keep placeholders only as supplementary hints. This fixes screen-reader announcement and click-to-focus, and applies to create/upload forms and dialog fields. Add a section heading (Panel title) to unlabeled create forms.

_Affected (9):_ `app/(dashboard)/coordination/jobs/page.tsx`, `app/(dashboard)/stock/vehicles/page.tsx`, `app/(dashboard)/stock/inventory/page.tsx`, `app/(dashboard)/stock/qr/page.tsx`, `app/(dashboard)/stock/client-qrs/page.tsx`, `app/(dashboard)/wireless/submissions/page.tsx`, `app/(dashboard)/staff/page.tsx`, `app/(dashboard)/scheduler/page.tsx`, `app/(dashboard)/leads/[id]/page.tsx`

### 7. Design-system primitives are re-implemented ad hoc instead of reused

Standardize on the shared primitives: use Meter (built-in track/fill tokens + role=meter/aria) for all progress bars instead of hand-rolled bg-gray-100 bars; use StatTile for metric boxes and Panel for section containers instead of bespoke divs and raw Card/CardHeader; and in components/charts/primitives.tsx render the linked StatTile variant with next/link's <Link> instead of a plain <a href> so KPI tiles use client-side navigation (this single fix upgrades every KPI tile across the company and dashboard pages).

_Affected (10):_ `components/charts/primitives.tsx`, `app/(dashboard)/analytics/page.tsx`, `app/(dashboard)/my-stats/page.tsx`, `app/(dashboard)/team/page.tsx`, `app/(dashboard)/financial/fuel/page.tsx`, `app/(dashboard)/support/clients/page.tsx`, `app/(dashboard)/wireless/submissions/page.tsx`, `app/(dashboard)/staff/page.tsx`, `app/(dashboard)/company/page.tsx`, `app/(dashboard)/dashboard/page.tsx`

### 8. Status is shown as raw snake_case text or by color alone

Route all statuses through a shared label lookup (STATUS_LABEL / KIND_LABEL) and render them as color-coded badges/pills, never raw uppercased snake_case like 'EN_ROUTE'. Where state is currently a single colored dot or uniform gray badge, pair the color with the label text (and add a legend) so state is distinguishable at a glance and not conveyed by color alone for colorblind/screen-reader users.

_Affected (4):_ `app/(dashboard)/coordination/jobs/page.tsx`, `app/(dashboard)/stock/requests/page.tsx`, `app/(dashboard)/wireless/submissions/page.tsx`, `app/(dashboard)/scheduler/agenda/page.tsx`

## All findings by page

### `app/(dashboard)/admin/page.tsx`

- **[medium] a11y** — The module toggle is a <span> with role='checkbox', aria-checked and tabIndex={0}, but it only has an onClick handler — there is no keyboard handler. It is focusable and announced as a checkbox to assistive tech, yet pressing Space/Enter does nothing, so keyboard-only users cannot toggle module access. _Fix:_ Add an onKeyDown handler that calls toggleModule(mod.key) on Space/Enter (and preventDefault on Space), or replace the span with a real <input type='checkbox'> styled to match.
- **[low] error-handling** — Load and save failures are surfaced via AlertBanner tone='warn' (amber). These are hard failures ('Failed to load access data', 'Failed to save'), which read better in the danger tone; amber understates them relative to the available tone='danger' style. _Fix:_ Use <AlertBanner tone="danger"> for the error state so failures are visually distinct from advisory warnings.
- **[low] hierarchy** — The page has no StatTile overview. The design system treats a StatTile summary row as a hallmark of good pages, and useful counts are already computable here (total accounts, accounts with grants, number of templates). _Fix:_ Add a StatTile row above the two-column grid (e.g. total staff, accounts with active grants, templates) for quick orientation.

### `app/(dashboard)/analytics/page.tsx`

- **[medium] loading** — No loading state. While the CRM store hydrates, `leads` is [] so every StatTile shows 0%/0d/R0, the 'Leads by Stage' card renders nothing (it filters count>0), and 'No lost deals recorded yet.' shows. A populated analytics page therefore first paints as a fully 'empty' dashboard, indistinguishable from a real no-data state. _Fix:_ Read `isLoaded` from useCrmStore and render StatCard/Card skeletons (e.g. animate-pulse placeholder bars) until data has loaded.
- **[medium] empty-state** — The 'Leads by Stage' card (lines 98-116) filters to `s.count > 0` before mapping. When there are no leads in any stage, CardContent renders zero rows — a blank card with a title and empty body, no message. _Fix:_ Add an explicit empty state inside the card (e.g. `stats.byStage.every(s=>s.count===0) ? <p className='text-sm text-muted-foreground'>No leads in the pipeline yet.</p> : ...`), matching the 'Loss Reasons' card which already does this.
- **[medium] consistency** — The progress bars (lines 106-114 and ServiceBar lines 185-190) hardcode `bg-gray-100` for the track. This is a fixed light-gray that does not respond to the theme token system and reads wrong in dark mode; it also duplicates the shared Meter primitive. _Fix:_ Replace `bg-gray-100` with a theme token (`bg-muted`), or better, use the shared `Meter` component from components/charts/primitives.tsx which already handles track/fill colors and includes role="meter" + aria attributes the hand-rolled bars lack.
